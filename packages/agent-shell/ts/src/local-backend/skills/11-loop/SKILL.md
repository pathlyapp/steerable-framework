# 循环执行（Loop）

用法：`/loop [间隔] <要重复做的事>`，间隔写在前后都认。

- `/loop 5m 查一下构建状态`
- `/loop 每 30 秒看一次日志有没有 ERROR`
- `/loop 盯着下载进度`（没写间隔 = 由你自己定节奏）

## 1. 先定三要素（缺一不可）

开始循环前必须确定并**用一句话告诉用户**：

| 要素 | 规则 |
| --- | --- |
| **间隔** | 用户给了就按用户的；没给就自己选一个合理值（秒级任务 10-30s，分钟级 1-5m）并说明理由 |
| **终止条件** | 「什么情况下算成功、可以停」。用户没说就自己拟一个并告知，例如「状态变成 success 就停」 |
| **最大次数** | 硬上限，默认不超过 10 轮。到达上限必须停下汇报，不允许自动续命 |

用户只说「一直盯着」而没有终止条件时，仍然要自己设一个上限并说明——**绝不允许无限循环**。

## 2. 选机制

| 场景 | 机制 |
| --- | --- |
| 总时长在几分钟内、用户想实时看到每轮结果 | **本轮内循环**（见下方 A） |
| 单轮间隔长、总时长跨越本次回答、或用户要继续聊别的 | **后台任务循环**（见下方 B） |

判断不了时问用户一句：「要我现在盯着（几分钟内出结果），还是放后台跑？」

### A. 本轮内循环

一轮 = 等待 → 执行 → 汇报变化。等待用 `local_exec_shell`，按真实 shell 选方言：

| shell | 等待命令 |
| --- | --- |
| PowerShell（Windows 默认） | `Start-Sleep -Seconds 30` |
| bash / zsh | `sleep 30` |

- 等待命令的 `timeout` 参数要大于间隔本身，否则会被判超时掐断。
- 每轮只汇报**变化**（「第 3 轮：状态仍为 running，日志新增 2 行报错」），不要把同样的内容重复贴一遍。
- 达成终止条件、或到达最大次数 → 立刻停止并给结论。

### B. 后台任务循环（task_run）

把**整个循环**写进一次 `task_run` 的 `task` 里——后台任务是独立的推理循环，看不到本对话，指令必须自包含，至少包含：

1. 要重复执行的具体动作（含命令、路径、判断依据）
2. 每轮间隔与等待方式
3. 终止条件与最大轮数
4. 结束时要带回什么结论

发起后告诉用户 `taskId`，以及三个跟进方式：`task_status` 查进度、`task_result` 取最终结论、`task_send` 中途改范围或加信息；任务面板里可以随时停止。

**不要**用 `task_run` 起一个「只睡一觉然后再起一个任务」的链条来模拟定时器——一次任务里跑完所有轮次。

## 3. 纪律

- **先跑一轮再进入等待**：用户要的是结果，不是先等 5 分钟。
- **不重复起同一个循环**：新建之前先用 `task_status` 看有没有同目的的任务还在跑；有就复用或先停掉。
- **连续 2 轮同样失败就停**：把真实报错告诉用户并给建议，不要一直重试刷屏。
- **每轮都必须真调工具**：没有真实 tool_call 就等于这一轮没跑，不允许凭空写「第 2 轮仍在进行」。
- 用户说停 → 立刻停止本轮内循环；后台任务则说明用 `task_send` 还是任务面板停止，不要再起新的循环。
